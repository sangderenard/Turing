# Local state backups (2026-11-10)

Tool: `examples/meowdoku/state_backup.py` (`snapshot`, `verify`, `restore`, `list`); operator wrappers `deploy\Backup-State.ps1`, `deploy\Restore-State.ps1`.

## What a snapshot captures

Into `<backup-root>\<UTC yyyymmddThhmmssZ>\` with a `manifest.json` (relative path, size, sha256, per-db row counts, skipped list, source root, tool version, duration):

| Captured | How |
|---|---|
| `sql/*.db`, `sql/*.sqlite` (accounts, job library, ...) | sqlite3 backup API (consistent while live, WAL included), then `PRAGMA integrity_check` on the copy; `-wal`/`-shm` are not copied |
| other files under `sql/` (`access.json`, `authz_policy.json`) | file copy |
| `content/`, `products/`, `jobs/`, `canvas/` | file by file; a file that vanishes or is locked is skipped and listed under `skipped` |
| `logs/` | only with `-IncludeLogs` |
| `secrets/` | only with `-IncludeSecrets` |
| `run/` | never (pid files, sessions, launch json are per-process) |

Not captured: the web dir (a product tree tied to a source revision), anything outside the state root, running-process state.

## Why secrets are off by default

The backup root is meant to be copied around (see off-machine below). Admin tokens, TLS keys and operator `.secret` files must not travel with it by accident. With `-IncludeSecrets` the new snapshot directory is restricted to the current user (the same icacls step as `operators.py`); if that fails the snapshot is refused and removed. Without secrets a restored root needs `operators.py bootstrap`/`rotate` to recreate credentials.

## Refusals

`--out` inside the state dir, or inside any git working tree (`git -C <out> rev-parse --is-inside-work-tree`), is refused. Retention (`-Keep`, default 14) runs only after a successful snapshot and deletes only directories named like a timestamp that contain `manifest.json`.

## Gate and grants

The scripts run `authz.py script-auth Backup-State.ps1 --user ...` like the other deploy scripts. `script_access` is keyed by USERNAME, not script name, so there is nothing per-script to register: an account must be in `script_access` and hold `deploy_scripts`. Operators bootstrapped by `operators.py` (admin, codex, claude, guest_agent) already are. To add one (admin's call, against the intended db, shown here with placeholders):

```powershell
& $Py "$Mk\authz.py" script-grant <user> --db <state>\sql\accounts.db --granted-by <admin>
& $Py "$Mk\authz.py" script-list  --db <state>\sql\accounts.db
```

## Usage

```powershell
.\deploy\Backup-State.ps1 -StateDir C:\dev\Powershell\srv\state -WhatIf      # prints the command
.\deploy\Backup-State.ps1 -StateDir C:\dev\Powershell\srv\state              # snapshot to srv\backups
python examples\meowdoku\state_backup.py list --out C:\dev\Powershell\srv\backups
python examples\meowdoku\state_backup.py verify --snapshot C:\dev\Powershell\srv\backups\<stamp>
```

Task Scheduler (documented only, NOT installed; the task account needs `MEOWDOKU_OPERATOR` and a readable password file, so prefer a dedicated operator account):

```
schtasks /Create /TN MeowdokuStateBackup /SC DAILY /ST 03:30 /TR "powershell -NoProfile -File C:\dev\Powershell\turing\examples\meowdoku\deploy\Backup-State.ps1 -StateDir C:\dev\Powershell\srv\state"
```

## Off-machine copy

Point a sync client (for example a Drive folder) at the backup root, or set `-Out` inside the synced folder (it must not be in a git tree). Sqlite files inside a sync folder are safe here only because each is a CLOSED snapshot copy that is never written again; never put the live `sql/` directory in a sync folder. Keep `-IncludeSecrets` off for any root that syncs.

## Restore drill

1. Pick a snapshot: `state_backup.py list --out <root>`; `state_backup.py verify --snapshot <dir>` must print `ok=True`.
2. Restore into a scratch root first: `Restore-State.ps1 -Snapshot <dir> -StateDir C:\temp\drill -IntoEmpty` (dry run), then add `-Apply`.
3. Open the restored `sql\accounts.db` read-only and compare row counts with the manifest; start a dev instance against the scratch root on a spare port.
4. Restore refuses while 8766/8768/47611 listen, and refuses when any target file (or any `sql/*.db`) exists. Restoring over a live root is manual: stop the servers, move the old state root aside (do not delete), restore into the now-empty root, start, keep the old root until satisfied.
