## Follow-on contract report (same date, no compiler edit)

`docs/compiler_convergence/thread_independent_scheduling_and_sync_operators_2026-10-31.md`
records the user's corrected contract: ordinary threads do not promise a
comparative schedule. Shared storage and possible effects remain represented,
but overlap alone adds no cross-thread ordering edge. Hardware lane choice
belongs to lowering. Proposed shader-derived graph terms distinguish a
control barrier from a memory barrier; scopes and memory semantics are
operator operands. This is a design report, not a newly implemented operator
set. The earlier region demonstration was amended to remove its implicit
cross-thread scheduling requirement.

The report now maps proposed `ControlBarrier` and `MemoryBarrier` nodes to
Turing's existing control-program and ProcessGraph dependency views. One
concorded operator identity must connect both projections when a single
synchronization operation supplies both. This is a documented design
boundary only; no barrier node was inserted into compiler source or SSA.
