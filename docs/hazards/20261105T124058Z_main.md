2026-11-05 MEOWDOKU CHESS EVALUATION FORWARD COMPILES, EXACT, SLOWER THAN NUMPY (MEASURED, Windows main):

- `examples/meowdoku/native_forward.py` traces the net's own `ConvValueNet.forward_both` plus the masked softmax of `evaluate` through `SSATensorProgram` and compiles it with `compile_native_graph_forward`; it runs with `prepare_artifact_execution`. No source rewritten, no shortfalls.
- Two channels, hidden 8, batch 1: compiled in 6.5 s; max value difference 1.7e-16, policy 2.1e-17 against the Python path.
- Full net (32 channels, hidden 128, 12 parameter tensors), batch 32: compiled in 2.6 s; max value difference 4.9e-16, policy 9.7e-17 over 35 positions (crossing a batch boundary).
- Speed: the kernel run is 137 ms per batch of 32 (about 58 M multiply-adds, roughly 0.4 G/s); preparation adds 14-19 ms. The numpy-backend Python path evaluates the same 35 positions in 9.8 ms. Not wired into the search.
- Cause: the program is 130 calls to `matmul_double` (the batched `W @ cols` lowers to per-position index_select / matmul / index_set). `matmul_double` is the compensated (Kahan) inner product by design, with a strided right-hand operand; its correction chain does not vectorize at O3. This is the authored precision contract, not an emission fault. A faster evaluation needs a sanctioned faster GEMM lane; none was substituted here.
- Kernel bank gemm on the net's layer shapes (`open_blas_bank` + `LaunchCoordinator.launch("gemm", ...)`, first shape 32x117x2048): the parametric gemm compile now REFUSES on main with `region value 12 (Mul in function 'gemm') has no settled dtype in the tensor, specialization, node, descriptor, planned scalar types, its operands, its call actuals or domain` from `_build_shell_hierarchy_plan`. Value 12 is an index product in the authored kernel. The ValueError is not a `BankRefusal`, so the coordinator's reference fallback does not catch it. The August record had this kernel admitted at about 1 GF/s; no timing was obtained today.
- GPU GEMM lane (`glsl_blas_deployment.build_gemm_deployment_pair`): its products are standalone executables that fill A and B with synthetic values inside the shell and write C to a file. There is no in-process entry that accepts caller matrices, so it cannot evaluate the net. Nothing was built around it.
- Batched matmul restored as one tensor operation (`SSATensorProgram.operation`, `ssa_backend.py`). Since 4abc962f (2026-08-15) a rank-3 operand was unrolled at trace time into per-position `index_select` / rank-2 `matmul_double` / `index_set`, so the op never reached the backend table although the backend declares `supports_native_batched_matmul`. It now emits one `batched_matmul_indexed_double` call with broadcast offsets (the routing rule `tensor_ssa_lowering` uses). Chess forward, 32 channels, batch 32: IR went from 130 `matmul_double` + 128 `index_select` + 128 `index_set` to 4 batched calls + 3 rank-2 calls and no slice copies; compile 2.5 s -> 0.8 s; max difference from the numpy path 8.6e-16 (value), 6.9e-16 (policy). Run time 130 -> 127 ms: the remaining cost is the compensated scalar body of `matmul_double` inside the batched kernel (profiled: a C harness with no Python in the process times the same DLL at 129.7 ms; the inner loop is vmulsd/vsubsd/vaddsd/vsubsd/vsubsd per multiply-add, no packed or FMA instructions).

- Tensor `round` is ties-to-even in the compiled kernels (numpy, torch and Python all round 0.5->0, 1.5->2, 2.5->2). The C reference used `round()` and the authored LLVM `llvm.round` (ties away), while the fused elementwise lane used `llvm.roundeven`, so one op gave two answers depending on fusion. Now C `nearbyint` and LLVM `llvm.rint` (default nearest-even mode). `llvm.roundeven` was tried first and broke the MCJIT verification engine of tests/test_c_backend_llvm_ssa.py: it lowers to a `roundeven` libcall the Windows CRT lacks, and the unresolved symbol left the module's other relocations broken (fold2d's memset call faulted; unfold2d, with no external call, ran). Bisected on a worktree (a025e79d / 15518c72 pass, adding roundeven faults, rint passes). 61 passed; compiled round matches numpy on ties fused and unfused.
