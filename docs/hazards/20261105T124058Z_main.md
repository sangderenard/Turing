2026-11-05 MEOWDOKU CHESS EVALUATION FORWARD COMPILES, EXACT, SLOWER THAN NUMPY (MEASURED, Windows main):

- `examples/meowdoku/native_forward.py` traces the net's own `ConvValueNet.forward_both` plus the masked softmax of `evaluate` through `SSATensorProgram` and compiles it with `compile_native_graph_forward`; it runs with `prepare_artifact_execution`. No source rewritten, no shortfalls.
- Two channels, hidden 8, batch 1: compiled in 6.5 s; max value difference 1.7e-16, policy 2.1e-17 against the Python path.
- Full net (32 channels, hidden 128, 12 parameter tensors), batch 32: compiled in 2.6 s; max value difference 4.9e-16, policy 9.7e-17 over 35 positions (crossing a batch boundary).
- Speed: the kernel run is 137 ms per batch of 32 (about 58 M multiply-adds, roughly 0.4 G/s); preparation adds 14-19 ms. The numpy-backend Python path evaluates the same 35 positions in 9.8 ms. Not wired into the search.
- Cause: the program is 130 calls to `matmul_double` (the batched `W @ cols` lowers to per-position index_select / matmul / index_set). `matmul_double` is the compensated (Kahan) inner product by design, with a strided right-hand operand; its correction chain does not vectorize at O3. This is the authored precision contract, not an emission fault. A faster evaluation needs a sanctioned faster GEMM lane; none was substituted here.
