# Cookie-owned action batches and clean motion contract qualification

Source-only qualification slice; no production restart or static publication.

POST /api/action/batch uses the existing session cookie, viewer refusal and access tier. X-Meowdoku-Batch: 1 is mandatory. {"op":"describe"} returns an opaque table_epoch and next_sequence. An execution body contains exactly table_epoch, sequence and actions (1–32 existing Table.action payloads, maximum 64 KiB). No body-selected table, profile, owner or credential is accepted. All edit-only actions are authorized before dispatch of any prefix.

One table lock holds across the ordered batch. This is not a transaction. Receipt.completed counts successful actions; a failed action may already have mutated state, and remaining actions are not dispatched. Receipt.state is the last successful state, not a claim about the failed action. Call GET /api/state to inspect after failure. No automatic retry of the failed suffix. Same latest sequence and canonical body returns its stored receipt; changed payloads, old evicted sequences and future gaps are rejected. Game replacement or process restart changes epoch. Receipts are not durable and do not provide exactly-once behavior across crashes. Existing non-batch controls can still change a game; this is not a snapshot/CAS protocol.

web/action_batch_client.js is an optional reusable transport, not included in the running page. It keeps the exact pending body after a lost response, refuses a second batch, and requires explicit recover(). Server receipts determine completion, never network delivery. No credentials or authority are derived from Nodus opaque routing IDs. A future native node must call through the session-authorized service adapter; this is not an independent scheduler or FIFO.

Validation: 42 Python tests (batch plus existing access suite), including real Meowdoku cell mutations on two isolated cookie sessions, privilege preflight, bounded input, partial failure, retry and epoch rejection. Node client lost-response/explicit recovery test passes. Separate test_meowdoku_motion_client_contract.py validates the existing published motion.wasm source digest and descriptor names, executes 128 seeded damped_axis inputs through the existing TuringWasmProgram shell and matches Python at 1e-12. This is Python/browser-Wasm evidence, not native Nodus engine proof.

Nodus worker owns real ThreadManager/FIFO/custom-node transport. Its native damped_axis compiler-product build hit a policy-denied Visual Studio telemetry endpoint. No alternate compiler retry was performed here; native tool integration remains unverified until the authorized build completes and descriptor input mapping is checked. Do not call this slice a complete deployed Nodus engine service.
