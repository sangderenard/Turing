Owner decision (2026-11-13): extend the alias chain (not a class-wide literal) so the single-write field transfer
reaches reads behind a constructor and behind an object held in a field.

What changed:
- Constructor alias. source_constructor_field_demand.constructor_initializer proves the ``__init__`` a class Call
  runs (value class ``source class construction``, the class's ``__init__`` declaration and no ``__new__``, the
  callee Name operand, the published FUNCTION_ADDRESS). candidate_constructor_receiver_aliases posts
  SOURCE_CALL_OBJECT_ALIAS (caller, Call, __init__, self) with the Call's own value as the actual -- the bridge
  SOURCE_CONSTRUCTOR_FIELD_EFFECT_DEMAND named (its alias check used formal 0, not ``self``'s Input id; fixed).
- Constructor binding (topological_reducer propagate_call_formal_numeric_types). A class Call carried only
  ``class_ref``, so no SOURCE_FUNCTION_REACHABILITY / SOURCE_CALL_ACTUAL_FORMAL reached ``__init__`` and its formals
  had no class. ``Holder(geometry="tetrahedron")`` -> ``__init__`` -> ``_load`` -> ``_configure`` ->
  ``configure_geometry``: the copy's specialized ``self.geometry = geometry`` constant refused "consumed as a host
  scalar ... missing_source_value_class" (also on clean d587fdad). The loop now resolves the class Call to that
  ``__init__``; arguments bind formals after ``self`` exactly as a method call's do. The result-class half of the
  loop is skipped for a constructor (its value is the instance, not ``__init__``'s None).
- Transfer (source_field_state_transfer). Two object steps, each a SOURCE_FIELD_TRANSFER_OBJECT_STEP row (new page):
  ``constructed`` (``__init__``'s ``self`` -> the constructed value) and ``field_held`` (the one written value of a
  single-written object field -> each read of that field its own transfer reached). Reach is computed to a fixed
  point, then posted field by field so each step cites the receipt that reached it. Every OBSERVED revision of a
  field is a read now (``define_offsets`` has one per geometry arm; only the latest, 228, was read, and the
  tetrahedron copy keeps arm read 80). A field the class body declares (storage ``class``) is excluded: a read could
  fall back to the class attribute.
- Reads in loops (YoungMan ``_build_triangle_map``: ``dtype=self.precision`` before the ``for bitmask`` loop and
  inside it; region value 56 unsettled). The reducer posts an OBSERVED revision for the FIRST read only; the
  in-loop read named no field state, and both read-site stamps refused any open loop. Now:
  ``loop_may_change_field`` -- a loop changes ``name.field`` only if its body assigns it or holds a call that may
  store into the receiver -- replaces "no loop" in ``entry_field_read`` and ``observed_field_state_cell``; and a read
  whose cursor is OBSERVED stamps that cell. The fold reads an OBSERVED cell's literal from the read that owns it
  (identity match) or, when that read already folded away, from the cell value's canonical identities on the book
  (one agreed literal). A field read whose own identity carries a book literal (the transfer's
  SOURCE_LITERAL_VALUE) folds to it -- previously the dtype projection read it but the read stayed live and the copy
  still demanded the record's ``str`` slot ("record scalar slot ABI lacks dtype ... field 'precision'", also on
  clean d587fdad).
- Audit: constructor aliases (recomputed proof, or a table-free check when no function table), the generalized
  transfer rows (TAG, previously flagged as incomplete 9-tuples), and the object steps.
- Tests: test_source_mapping_get_copy_state_demand pinned the unproved state (no reachability/alias to
