## Boundary and actual changes

The user requires AST to end at source ingestion. Required grammar information
must become typed graph facts there. Every new decision and rewrite must read
and write concordance; recording an explanation after guessing is insufficient.
This migration is NOT complete. Existing control-placement helpers still read
AST/source coordinates, including helpers used by the retained native dispatch
path. They have not become an AST-free control graph merely because their
operation/operand readers now use the book.

Removed source_exceptions.py and its normalization/final-order calls, AST-based
exception occurrence/source-signature overrides, exception-slot control
placement, scope-membership fold workaround and mutex context transformation.
Removed the AST-built ThreadRegion projection, rather than preserving a stand-in
as evidence of dual-IR scheduling. SOURCE_THREAD_REGION now explicitly records
concorded_control_topology_required. No paired control/memory barrier region or
ASAP/ALAP region result is currently provided by that path.

Try/TryStar/Raise admission now reads INGESTION_VALUE NodeFact and posts
NATIVE_EXCEPTION_CONTROL_GAP before raising MissingExceptionControlTopology.
With scopes similarly refuse missing resource entry/exit/cleanup topology.
This currently also rejects pre-existing Condition/resource-scope tests. That
is a regression and unfinished migration, not successful native exception work.
Native fundamental operator/error-record/shell-channel foundations remain.

At ingestion, SOURCE_OPERATOR_KIND captures registered BinOp/UnaryOp identity,
SOURCE_FORMAL_ORDER captures source signature order, and synthesized constants
publish SOURCE_LITERAL_VALUE at their actual writer. Scalar synchronization
literal proofs use these facts and actual operand positions, not AST evaluation.

The incumbent _set_operands writer now publishes PROCESS_GRAPH_OPERANDS from
its existing role/ordinal positions and transition cells, including the first
unchanged snapshot. Fork projection retains this page. A first implementation
mistakenly treated physical parent-list order as semantic position: the
returned_growth case reordered callee/arg:0 without changing their positions,
then REVISE correctly refused unchanged causes. Corrected the snapshot's
serialization of the existing role/ordinal map. No dependency or scheduler edge
was added to fix it. The case subsequently compiled/executed successfully.

Converted new dispatch, lock-box, thread-table, dtype and C readers to exact
process-operation, operand, callable, closure-binding, aggregate-layout,
capture-type and compile-policy facts. No receiver-name or method-spelling
classification. Literal evaluation declines mutable lexical reads. Captured
storage write classification follows typed IndexedStore and base operand edges.
The capture-layout reader initially queried authored scope for canonical IDs;
observation showed the existing canonical layout under lexical_read_scope.
Fixed that reader key instead of reconstructing leaves from AST.

SSA_PROCESS_CALL is published at SSA materialization from the source contract.
It records actual arguments, captures and expanded worker bindings. Removing
unused context operands first revises that contract using context facts, then
changes the instruction. C ThreadCreate reads it and checks actual SSA against
it. LOWERED_SOURCE_FUNCTION is published at the materialization writer; its
address, actual SSA entry and source CONTROL_PROGRAM must agree through exact
provenance. Thread body selection no longer trusts source-function metadata.
C completion/lifetime analysis reads SSA_BLOCK_GEOMETRY, validates actual SSA,
and derives its policy from those geometry cells. No fault-unwind exemption is
inferred from an attribute: every Ret currently needs completion of borrowed
state. C fence policy already reads/validates source and SSA receipts.

Division instruction creation and C arm selection now read the compile-policy
cell. Instr.failure_arms_for(book) replaces the attribute-authoritative property.
Audit checks were added for operand/literal proof provenance, ordered argument
packs and SSA process calls; thread-body checks read materialization facts.
These checks validate records; a clean mapping audit does not prove the whole
compiler has an AST-free boundary.
