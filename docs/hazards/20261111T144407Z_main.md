2026-11-11 THE PART-BY-PART BUILDER WRITES A GOAL DOCUMENT (MEASURED, local Windows):

Owner, on what the Goal document is: "The processed result. A new format with linking syntax and abi/api comment
tables, ready to be a graph representation of itself because then anything can work with it".

Built here: `source_divider.write_goal_document` -> `<job>/goal.goal`, in the format `speaktome.goal-document.v1`
(SpeakToMe repository, `speaktome_goal/`, loaded through `rest_api.goal` as the manual is). `recompose` writes it
after the units record. `deploy/bake_site.py --goal-file` bakes it into pages.

What each table is filled from, so that nothing in it is this function's own opinion:
- unit text: the compiler's cut (`partition_authored_source`), then only the top-level statements reachable by name
  from the unit's own definitions; a definition another unit provides is left out.
- `link`: the triage's `deps` (piece ids). `reference` when the provider's definition was left out and the text names
  it; `carried` when it could not be separated (a method of a kept class, a nested function).
- `api`: the authored formals and return annotation of each entry, unparsed from the source's AST.
- `build`: the completed entries of `attempt.json`: target language, the exported symbol the lowering returned,
  product name, sha256, and the id of the block that holds the bytes in `record.dream`.
- `abi`: the `entry_points[].parameters` of the product's own `.api.yaml` (wasm and js write one; c and llvm do not,
  so their builds have no abi rows).
- `target` (document): per language, units built for it; the goal is achieved for a language when all are.

Measured (`tests/test_meowdoku_source_divider.py`, 9 tests):
- Three chained functions, no compile: `step`'s text holds `def step` only; `RATE = 2.0` stays with `double`, the one
  that uses it; link row `double -> piece-N : double (reference)`; all units `source`; nothing achieved.
- A constant both functions use, itself defined from another constant: both statements stay in each unit, and the
  unit executes when the reader supplies what its link names.
- Three real wasm lowerings: the goal is achieved for wasm (3 of 3); every build row's hash equals the content hash
  of the block it names in the units record; abi rows carry the authored parameter name as `source`.
- A real js + c job (build/site-baked/example-goal.goal): two units lowered for both, one stays source, so the goal
  is achieved for neither; baked into 11 pages.

Hazard found and fixed before commit: the first cut removed only the provider's definition and left behind a constant
that only the provider used (`RATE` inside `step`). The cut now walks from the unit's own definitions.

NOT what this is:
- Linked BUILDS. Each listed product was built from a part that carries its dependencies by copy; `step`'s product
  contains its own `double`. The document states the joins. Building the units joined is the compiler's
  `linked_dependencies` path and has not been attempted.
- Nodus nodes. `as_graph` is a generic graph, not a `nodus.graph-definition.v1`.
- Multi-language. Only the divided language's units are in it; other blocks of a dream input are not units yet.
- A proof that a goal "achieved" for a language runs: achieved counts builds, it does not execute them together.
