# First-channel jukebox, request rotation, votes and billboard

Extends the existing Nodus Radio, not a new audio engine. SQL tables are owned
by `nodus_radio_jukebox` in the StatePaths accounts database, schema version 1.
No live database or station configuration changed in this work.

## User and administrator controls

The signed-in shared-header Radio panel now includes a station catalogue,
Request song, removal of one's own queued requests, a 0–5 rating selector for
the currently playing song, and billboard charts. Ratings are optional. Zero is
a real vote; a later vote by the same user updates that user's vote for that
song rather than inflating the count. A stale play ID is refused with 409.
Charts are a SQL aggregate view ordered by average descending, then vote count,
then song ID for deterministic ties. This simple chart is not popularity or
confidence-adjusted ranking. One identity gets one vote per song; the system's
multiple-account policy is unchanged.

Every account with the existing `account_manage` capability gets channel
Start/resume, Pause after this song, Skip current song, and removal of any
queued request. No single initiating admin owns the jukebox controls. Existing
PA speaker controls remain separately owned as before; jukebox operation does
not implicitly start server speakers. No menu opening or GET starts a producer.

`GET/POST /api/radio/jukebox` uses existing sessions. Mutation requires bounded
JSON, the existing same-origin Radio header, and authenticated ownership or
admin capability. User requests supply catalogue IDs, never local file paths,
ports, executable names, another user's identity, or arbitrary source URLs.
Request lists are limited to 100 pending songs per user. Non-admin responses do
not expose other users' account IDs. Catalogue paths and native settings are
never returned. Admin actions and request edits are recorded in SQL.

## Rotation and playback boundary

One song per nonempty user list per rotation. Each user's own list is FIFO.
New or returning users join the tail of the rotation; empty lists are skipped.
Selection is one BEGIN IMMEDIATE transaction. A current play blocks another
claim, and an opaque token fences completion so stale EOF cannot finish a newer
song. Queues, turns, outcomes and votes survive process restart. A stale current
play after service failure requires explicit ownership recovery; it is not
silently replayed or cleared on resume.

The native runner connects this store's `claim()`/`finish()` to the existing
Nodus file-source rows and their verified PCM EOF. Its own receipt describes
source gating, config, build verification and remaining playback limits.
`run/nodus_radio.json` gains `jukebox.songs`, each with stable `id`, `title`, and
operator-controlled absolute `path`; native executable/ports belong in the
runner's `jukebox.native`. Do not use a repo directory for this local config.

## Studio interface

The existing widget publishes `nodus-radio-signal` only from current accepted
polls and publishes unavailable on dismissal/error. The Studio integration owns
its opt-in controls. Its server call samples real configured Radio telemetry,
not client-supplied amplitudes. The trusted in-process source peer/title override
lets the existing spectrum snapshot follow successive native source instances
without editing the station config or accepting HTTP peer overrides.

## Verification

Core tests cover round-robin/FIFO order, joining, empty queues, persisted current
play, eight concurrent claimers, stale completion token, pause/finish, owner vs
admin removal, rating zero/update/count, invalid vote/action types, removed
catalogue entries, auth and CSRF. Existing header fixture tests cover member and
admin, double request clicks, zero vote submission, lazy polling, rapid toggles,
Escape/outside close/unload and stale responses. These are local fixture tests,
not proof of deployed endpoints, real user sessions or audible playback.

Focused Python radio suite, header fixtures, server AST and git diff checks run
locally. No sound, GPU, server restart, push, deployment, or live account/config
change. Existing network-policy block was not bypassed.
