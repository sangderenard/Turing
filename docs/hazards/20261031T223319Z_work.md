## Implemented thread-table C slice

The existing native task API in turing_pool.c/h implements launch/wait; the
new turing_thread_table.c/h manages per-instance context/lifecycle and owned
worker error records. `ThreadCreate` does not start a task. Start launches its
actual SSA worker function. Join waits; repeated joins are allowed. Invalid
start/join states report a native RuntimeError instead of touching bad handles.
No separate Python executor, in-process C runner, handwritten C worker, native
lane-selection heuristic, or implicit shared-storage lock was added.

Captured bounded sequence views alias actual parent storage. Numeric scalar
captures and scalar arguments are copied to each native activation context.
SOURCE_THREAD_ARGUMENT relates the exact source tuple member to the exact
worker formal before expansion; the loop factory now copies the current SSA
induction Phi instead of passing a dtype-less aggregate placeholder. The
concordance audit reads these new argument facts. C_THREAD_ACTIVATION records
worker, physical binding decisions and normal-return join lifetime proof.

to keep dangling pointers into an owner frame. Runtime cleanup waits before
freeing captured activation storage on an owner fault.

Worker errors are native records (code/type/static message/worker token and
function). Join returns normally and reports the retained error on the
separate shell reporting channel. Synchronous active errors and reported
worker errors are separate TLS slots. The shell returns exit7 and publishes
no output file for an unhandled error. Channels retain their first error;

whose explicit extraction contract permits it; basic mechanics do not use
Python as their runtime implementation.
