## Ingestion and actual writer changes

`source_exception_ingestion.py` reuses the native record/control conversion
vocabulary from the withdrawn implementation. Its temporary AST is an ingestion
representation, not runtime Python. It proposes a converted function body on a
copy, publishes SOURCE_EXCEPTION_INGESTION from exact authored source spans,
then applies that body at the ingestion writer. Generated nodes register their
INGESTION_VALUE through both the occurrence and conversion; SOURCE_EXCEPTION_NODE
records that join. Nested worker conversions retain their own provenance.

ExceptionNone/Make/Take/Active/Match/Raise/IndexType/Length become ordinary typed
SOURCE_PROCESS_OPERATION and SOURCE_EXCEPTION_OPERATION nodes. Existing early
control-IR ingestion gives them DispatchBlocks and placements before folding
and region carving. Late lowering reads the ingested exception-operation cell.
The existing C record runtime and fundamental SSA division safety arms supply
execution; no C++ EH, longjmp or host Python exception callback was added.
The conversion does not insert a divisor prefilter or postfilter.

Protected for/while loops preserve condition evaluation, caught errors,
exhaustion, explicit exits and finally through these explicit operations/arms.
The new while case compiles an authored worker, starts/joins it, and executes
the generated standalone C binary for n=0,2,5 under both scheduling policies.
The tests compare final output to that same authored Python program.
