2026-11-02 TITLE (MEASURED, where): Empty class constructor has no physical producer

Current bounded source, run through ProcessGraph reduction and sanctioned
`lower_ast_source_to_ssa` in about 5 seconds:

```python
class A:
    def value(self) -> int: return 1
def root() -> A:
    return A()
```

ProcessGraph Call1 has `class_ref='A'`, a canonical operand cell for its
callee Input0, and SOURCE_VALUE_CLASS `('A',1,'source class construction')`.
The planner posts EXECUTABLE_NODE for Call1 as DISPATCH_METADATA with rule
LINKED_REFERENCE. It posts no CALL_BINDING for this constructor. In the
linked ProgramABI pass, `_physical_type_arms(root,1,{'python_type':'A'})`
returns `()`. No VALUE_TYPE_ABI arm exists for Call1. The control SSA
function has no arguments and only `Ret []`; there is no SSA_VALUE cell for
the returned object. The final audit correctly refuses:

`single_empty_class_probe__root value 1: the source returns 1 value(s), but
a Ret in block entry returns none`.

In the existing constructor frame linker (`fortran_c_shell.py` around
46000), a class Call gets caller-owned record storage only by resolving an
authored `__new__` or `__init__` method and a nonempty constructor record
table. This class has only `value`, so `constructor_method is None` and the
linker continues without a frame. That observed branch explains the missing
physical producer; source class identity alone cannot allocate an instance.

The related source `return A().value()` does lower successfully: its method
Call has a scalar int64 ProgramABI and SSA Call/Ret, while the A() value
remains an unphysical source operand not emitted as a runtime object. That
case does not establish a physical A arm. Existing
SSAValueUnionDescriptor shared-reference storage requires an actual common
physical payload cell and tag; neither exists for A() or the earlier A/B
merge. The named `native_class_union_arm_layout_missing` refusal remains.
No compiler or test source was edited for this investigation.
