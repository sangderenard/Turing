# Render jobs library frontend (not published)

Added `marble_jobs.html` and `marble_jobs.js` with account/profile-owned job listing,
queue position, actual error text, image/HDR links and the existing cancel action.
The Studio mounts the same module in My jobs beside the exposure controls.
No new render is started by selecting or viewing a job. Polling preserves selected
jobs, pauses while hidden, and survives browser back/forward cache restoration.

Contract: GET `/api/marble_photo/jobs` supplies owner-filtered `entries`; current
profile cookies remain same-origin. POST `/api/marble_photo/cancel` sends only the
selected digest. No invented resume, scheduler or multi-GPU controls are present.

Verification: Node syntax and `tests/meowdoku_jobs_check.mjs` passed listing,
selection retention, queue labels, encoded image/HDR URLs, cancel body, network
error, empty list and stale response disposal checks. No production endpoint or
browser visual test has passed yet. No active render was touched.

Publication held pending backend Nodus FIFO integration. Exporter includes both
new assets; Studio HTML has a scoped script/section insertion. Do not replace live
bootstrap or HTML wholesale because other workers have unpublished features.
