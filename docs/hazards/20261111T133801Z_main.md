Hazards found:
1. A canvas host keeps only the contract ports its CANVAS FILE declares. `run_canvas.py --acquire P` before the load
   creates the negotiator, not a port: the load restores the file's records and nothing else. Measured: acquiring
   `studio.product` beside `gui.proof` printed one port. New tool nodus `tools/add_contract_port.py` adds a declared
   port to a canvas (verified: two ports listed, both served).
2. The live canvas `build/meowdoku/canvas/messenger.canvas` does NOT yet declare `studio.product`. Until it does, the
   supervisor logs "the host declares no such contract port; pictures stay off" and `/api/show/pictures` answers 503.
   Adding it needs the live Nodus host stopped (its port 47611 is bound while it runs).
3. Git Bash rewrites an argument that begins with `/api/...` into a Windows path; a helper called that way reported
   "invalid or incomplete response" against a healthy service. Use PowerShell or MSYS_NO_PATHCONV=1.
4. The client work-sharing bridge options of the HTTP photo path are not carried by `commit_studio_ray`; a payload
   asking for client intersections is refused by `PhotoJobs.start` itself.
