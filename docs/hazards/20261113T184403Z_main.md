Rules now holding:
1. `_call_result_bindings(..., result_is_output=True)` when the callee has one output and every return site is a
   VALUE (RETURN_SITE_CONTAINER, read through `return_container_kinds`): output path (0, *p) binds the caller's
   projection (*p) -- the call result IS that output, exactly as one output over returns of different arity already
   binds (`_return_output_arms_members`).  A tuple display return (`return (t,)`, kind TUPLE) keeps its paths.
2. `call_result_descriptor` also enters (instead of returning early) for a call whose value is the last identity of
   one of its caller's positional outputs when every callee return site is an authored TUPLE.  Its decision is the
   new page RETURNED_AGGREGATE_CALL (caller shape scope, call value) = (callee, "tuple", call identity cell, the
   callee's RETURN_SITE_CONTAINER cells), DERIVED from those cells; the CALLSITE_DESCRIPTOR_REUSE "computed" row
   also derives from it.  The existing member publication (`_publish_callsite_return_members`) then mints the call's
   members, so outer's output carries mid's member identities and rule 1 binds them to root.
- Audit `_returned_aggregate_call_findings`: kind "tuple", call cell and every container cell are the receipt's
  sources, every container cell is TUPLE.  A tampered row (container cells dropped) is reported.
