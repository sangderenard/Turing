# Borrowed string fields in direct record sequences

Observed: authored str fields were marked as scalar int64 by lexical annotation ingestion even while their aggregate kind was str. A list[Record] projection consequently loaded one row handle as the field contents. Ordinary control equality then compared scalar values or coerced both fields to truthiness instead of comparing their complete glyph spans.

Repair: authored str field declarations retain their existing glyph-span ABI, distinct from explicitly declared scalar vocabulary tokens. Direct and nested record-row projections now select per-field borrowed child arenas with independent lengths, strides and capacities using the existing child-table selection/GEP machinery. Exact resident string comparisons defer to the established structural full-content sequence equality helper. The selected GEP publishes its element dtype at its producer. Record tables merge rather than overwrite; repeated reads bind physical columns/counters with their exact graph and sequence-descriptor source cells. Logical descriptor IDs that are not defined SSA values are not posted as physical aliases. No new comparison kernel or shared-instance handle contract was introduced.

Verification: six native regressions pass for direct, nested and repeated field reads with == and !=. Cases cover independent/reordered field handles, unequal strides, empty strings and rows, unequal lengths, Unicode, repeated calls, and unchanged caller buffers. Earlier focused run including prior scalar-token and numeric-array exclusions:11 passed. Immediate HEAD baseline for the expanded suite:40 passed,24 failed; the six new tests fail there. Final candidate:46 passed,18 failed; the failure-set difference is exactly the six new tests, with zero candidate-only failures. Mapping audit:28 rows across2 functions,0 findings,0 unsourced,latch CLOSED. Independent mixed-input native probe retains both an ordinary Settings record and the sequence-row record, returns8 as expected twice, and emits no LLVM shortfalls. Its optional str variant refuses explicitly. Final actual GraphSolver rerun still has the same four findings.

Limits: this is a borrowed read-only field view, not general mutation, allocation or return-of-view support. Optional borrowed spans explicitly refuse until a presence-aware projection exists. The raw ABI requires valid handle indices, pool lengths, strides and live caller buffers; it does not add runtime bounds validation. Independent pools must not be described as SSARecordInstancePoolDescriptor, whose contract is one shared record handle. The experiment putting parent-pool inputs in selected-field value_ids was refused because they are not selected sequence members and was removed. Actual GraphSolver compile_nodes still has four concordance findings, including the literal 'master' comparison in a filtered comprehension; this is not full GraphSolver LLVM completion. No merge, push or deployment.
