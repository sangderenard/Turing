# Parametric hull investigation checkpoint (intercept-sharing priority)

No new hull law or geometry replacement was written. User suggested piecewise spherical-coordinate lambdas compiled to LLVM; priority then moved to actual client intercept work sharing and Nodus messenger.

Existing sources found:
- Older standalone `C:/dev/Powershell/geometry`, HEAD9712872 (2025-07-27), exposes `include/geometry/parametric_domain.h` and `src/geometry/parametric_domain.c`: continuous axes, periodic wrapping, inclusive/exclusive boundaries, discontinuities and extrapolation. This is a real domain contract, not a verified ray-surface evaluator or LLVM integration. README also names parametric_transform, but no such tracked implementation was established in this pass.
- Speaktome `tensors/riemann/geometry_factory.py` assembles Transform/GridDomain/ManifoldPackage. Older training notebook `1733612620_CompositeGeometry_Shape_Shuttle_YoungManAlgorithm.py` contains CompositeGeometry/Shape and spherical jitter transforms. These are historical candidates, not demonstrated exact hull intercept kernels.
- Spectral `camera_designer/parametric_surfaces.py` already has ParametricSurface.intersect/intersect_batch/glsl_intercept_fn plus plane, sphere, conic, polynomial, toric, cylinder and CatmullRomMesh implementations. `optical_volume.py` defines closed regions between surfaces. These are preferable integration authorities to a second shape registry.
- Spectral T1/T2 `csrc/shaders/ray_refine.comp.glsl` plus `csrc/include/triangle_groups.h` expose POLY_BARY, SDF_SPHERE, SDF_SADDLE and PARAMETRIC_LENS payloads. Refinement after a coarse hit is not by itself a complete arbitrary-ray intersection solver. Neural transport is explicitly refused without required optical accounting.
- Turing `web/dice_mesh.js` is the current bevel authority: convex hull inset by r then offset by radius-r ball, with face/edge/corner patches tessellated into closed mesh. Current face/marking relief modifies that boundary further. A radial function only covers shapes star-shaped about its declared origin; it is not universal for every arbitrary hull/relief.
- Spectral `parametric_curve.py` PiecewiseEnvelopeBuilder is gated temporal torch envelope evaluation, not an identified LLVM spatial hull kernel. `camera_software/lens_manifold.py` PolarChain uses local polar ray frames through optical surfaces, not die boundary shape parameterization.
- Turing `src/compiler/abstract_ui_bvh.py` packs exact Spectral-compatible twelve-float nodes and triangle permutation for contact kernels. This is a builder, not an existing compiled query traversal.

Reusable Nodus authority: `include/common/thread_pool.h` Job/JobBatch/TensorArenaView; `nodus_headless_abi.h` compiler product deployment and tensor handle APIs; existing contract negotiator/socket owns opaque work IDs and generation/deadline exchange, not raw tensor payload authorization. Native worker owns this integration.

Required geometry semantics before a unified hull evaluator: explicit patch domains, deterministic seam ownership, exact local-to-world transforms and inverse-transpose normals, conservative bounds, all valid roots/nearest-positive selection, grazing/tangency behavior, inside/outside and material side identity. A smooth normal alone cannot replace geometry. For the current die bevel a relief-free d6 face/cylinder/corner radial evaluator is a sensible bounded future test, but remains a design suggestion until the older intended technology is identified and selected. Do not claim it implemented.
