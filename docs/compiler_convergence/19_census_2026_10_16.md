## Own-cause groups

* **23 units, one bug (fixed)**: `AttributeError: 'str' object has no attribute
  'name'`.  `source_native_type_tests` in `ssa_object_context.py` passed page-name
  strings (`"source_python_identity_concordance"`, `"static_reference_use"`) to
  `IdentityBook.latest_ref`, which takes a declared Page.  Three sites now pass
  `SOURCE_PYTHON_IDENTITY` / `STATIC_REFERENCE_USE`.  Guard:
  `tests/test_page_api_use.py` fails if any `latest_ref(` is given a string
  literal.  NOT verified in the units (the frozen plan refuses a replay after a
  toolchain edit; an `isinstance` probe module hit the undeclared user-class
  storage refusal first) -- the next run is the check.
* **12 units**: "formatted glyph component has no resident producer ...
  projection='scalar'" (e.g. 16, 19, 37, 44, 78, 100, 132, 157, 231).  An f-string
  component whose value is an unclassified scalar (typically `{key!r}`); the
  runtime-`!r` redesign deliberately leaves those unresolved instead of calling
  CPython.  They need a classification of the scalar or an authored formatter.
* **Provenance family (units 3, 25, 29, 71 and some inherited)**: the
  dependency-link detector refuses a book with unsourced cells.  Writers still
  bypassing `IdentityBook.post`: `record_field_access*`,
  `record_field_layout_concordance`, `record_scalar_shape_concordance`,
  `field_slot_storage_concordance`, `control_block*` and `ingestion_value` in a
  copy-on-read `|fork` scope, and ids minted outside a Novel post.  This is the
  concordance principle applied: each is a migration to `post` with derived
  provenance.
* **49 partial units**, by shortfall: 15 `native-result-layout-mismatch;
  structural-output-shortfalls;unresolved-required-source-values` (e.g. unit 54
  `_is_authored`), 11 `unexplained-public-arguments;unresolved-boundary-types`
  (e.g. 59 `validate_heap_context_projection`), 6 `unexplained-public-arguments`
  (56 `dtype_layout.resolve`, unlocks 14), 5 `unresolved-boundary-types`
  (144 `ensure_declared`, unlocks 7), 4 `structural-output-shortfalls`.  Not yet
  investigated.
* **Long tail (1-3 units each)**: type ABI storage for an undeclared user class

## Round 2 (2026-10-17): five narrow agents on the ranked lanes

Receipts of the census were copied to `build/census-2026-10-16` (json only).  Each
lane ran with the same limits (no bootstrap, no contract edits, no repo-wide
runs, no commits); verification was by focused tests and tiny probe modules
compiled through the public entry with the bootstrap's own contract construction
(frozen-plan replays are refused once a toolchain file changes).

* **Unit 31 (`IdentityPage._reindex`, unlocks 113) -- fixed.**  The `int(None)`
  was not the `.values()` loop: it was the dict comprehension
  `{column: position for position, column in enumerate(self.columns)}`.  The loop
  composer deliberately records a two-target `enumerate` element projection as
  `None` (the source's only column); the GLSL binder already reads `None` as
  column 0; `lower_loop` handled it everywhere except one call,
  `projected_native_type_tag(..., int(column_projection), ...)`, now
  `0 if column_projection is None else int(...)`.  Regression:
  `test_enumerate_element_projection_none_lowers_in_keyed_reindex` (verified to
  fail with the fix disabled).
* **Unit 3 (`decimal_integer_glyph_tokens`, unlocks 113) -- fixed, and it was not
  a mint outside a Novel post.**  Unit 1's own book holds the Novel mint rows; an
  imported accepted SSA body keeps that book as `metadata["accepted_ssa_component"]
  ["identity_book"]`.  `CorrelationTable._unsourced_worklist` only read the
  composing unit's mint page, so 11 ids were flagged.  It now reads mint edges
  from the function's accepted-component owner book (still requires a mint row in
  a book; nothing exempted).  On the unit-2 artifact: 11 findings -> 0.
* **Unit 25 (`IdentityBook._ref_from_key`, unlocks 97) -- half fixed.**
  `ingestion_value` in the `|fork` scope: `_synthetic_device_scalar_shell`
  (`glsl_deployment_strategy.py`) added three nodes to the real callee graph with
  only scratch-scope rows; they now get derived `ingestion_value` rows in the
  graph's own scope.  `control_block` / `control_block_placement` remain: the
  glyph-sequence builders in `resident_sequence_materialization.py` (~106, 144,
  190) emit a `clear` and several `extend` mutations that share one
  `effect_node_id`, so they map to one `control_block` row with different facts.
  OPEN QUESTION (owner): is a step block's owner (a) a step discriminator in the
  `control_block` row key (schema change, touches the placement reader), or (b) a
  per-step row derived from the `source_glyph_sequence` cell carried on
  `ControlSequenceMutation` like `ScalarFieldWriteBlock.field_state_cell`?  The
  second adds no schema.
* **Units 29, 71, 205 (unlock 110 / 45) -- pages migrated, units not
  reproduced.**  `record_field_access`, `record_field_access_path`,
  `record_forwarding_edge`, `record_field_layout_concordance`,
  `record_scalar_shape_concordance` (declared as `RECORD_SCALAR_SHAPE`, lifecycle
  `LOWERING/None/REPAIRS`) and `field_slot_storage_concordance` now go through
  `_frame_post` / `post` with derived cells (new helper
  `forward_record_field_roles`).  `CorrelationTable.findings` on small record
  sources no longer flags them.  STILL RAW, named by the probe:
  `receiver_nested_record_field_concordance` (`fortran_c_shell.py` ~9292, blocks

  OPEN QUESTION: which cell does `receiver_nested_record_field_concordance` derive

  `class_field_declaration`?  The `unaccounted-formal` float64 finding in units

* **Glyph scalar components (12 units, units 44/37 unlock ~98 each) -- nothing
  changed; in all 12 the component's class is not known to the concordance, so no
