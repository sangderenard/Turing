## Round 3 (2026-10-17): validation diagnostics own their identities

The next provenance run reached 327 units and failed in SSA lowering for unit
038 (`_validate_fact`) and unit 045 (`identity_spill._replace_cells`).  In both
cases the rejected formatted value was the argument of an exception constructed
by a terminal raise guard.  The control planner already replaces that guard with
the existing `ValidationBlock`, whose native lowering consumes the predicate,
error code and exception identity; it does not consume or display the authored
Python message.  Glyph materialization nevertheless tried to construct every
`JoinedStr` recipe before control lowering, so it demanded a resident `repr`
producer for an `Any`/unclassified value that had no native consumer.

This was repaired as an identity/use contract, not by recognizing the two
functions or the shape of their strings.  `ValidationBlock` now records the
exact source value ids supplied only to its authored exception diagnostic.
`post_control_program` turns those ids into cells in the existing
`control_block` concordance fact.  Resident glyph planning reads those cells
back through the graph identities and omits only a diagnostic `JoinedStr` owned
by compiled validation.  The authored fallback retains its original Python
exception and message.  All other unknown formatted values still take the
existing strict refusal path.

`Any` and `object` already have the general transport representation:
`storage=reference`, `dtype=opaque_ref`, rank zero.  That fixed-width identity
handle is sufficient for transport, storage and identity operations.  It is not
a generic native `repr` implementation and this repair does not pretend it is.
The additional fact answers the separate question of whether a value has a
runtime formatting consumer at all.

The dynamic `_validate_fact` remainder was repaired through an API declaration,
not Python runtime inspection.  `ProgramABIValueBinding` accepts one declared
type identity or a closed `type_expectations` union.  Those identities are
joined to the existing source-class concordance at compile time.  At the native
section boundary the material is its declared C-compatible payload plus an
`int64` alternative token.  `Page.fact_type` can declare a class tuple; its
record field is likewise an integer vocabulary token.  Native `isinstance`
lowering explicitly joins the subject's VALUE_TYPE_ABI alternatives and the
target vocabulary through canonical subtype identities.  Dense ordinals from
the two independent vocabularies are never compared directly, and no class
object, PyObject or CPython ABI crosses the bootstrap contract.  A real public-
entry lowering of `_validate_fact` cleared the former structural output.

## Round 5 (2026-10-17): one physical reference for a closed class domain

The next fresh run failed unit 038 (`_validate_fact`) while lowering the dynamic
native type predicate.  The source-class vocabulary was known, but the exact
`fact` input had no VALUE_TYPE_ABI receipt.  The wrong boundary was not a
missing Python object.  `fact: Any` already declares the physical sectional
representation: one `opaque_ref`, which is the compiler's fixed-width native
reference value and is exposed through the existing ctypes-compatible ABI.
What was absent was the independent semantic class token used by native
`isinstance`.

ABI settlement now examines the existing native type-test receipts before
VALUE_TYPE_ABI publication.  For a dynamic predicate it joins the exact subject
parameter, its authored reference ABI, the target's
`SOURCE_PAGE_FACT_CLASS` vocabulary, and any static predicate identities over
the same subject.  The resulting receipt is attached to the subject value and
retains the source concordance cells.  This is an API-declared expectation: it
does not inspect a Python object at runtime and it does not derive a class from
the bits of the opaque reference.

Closed semantic unions whose arms have the same physical ABI now publish a
`shared` value-union layout.  All class alternatives name the same one
`opaque_ref` payload, and one `int64` tag names its semantic class.  Adding a
class extends only the token vocabulary; it does not add another payload
formal.  Side-by-side layout remains unchanged for unions whose alternatives
really have different physical storage.  The shared descriptor survives final
module assembly, formal accounting treats the tag as part of the declared
parameter ABI, and concordance publishes the tag formal under the parameter's
`.__type_tag` key.

## Round 7 (2026-10-17): jobs is concurrency, not a hidden stage limit

A clean growth invocation stopped after 12 compiled units with 315 pending.
The receipt showed no failure: `stopped_after_failure=false` and all 12 admitted
units were `compiled-unverified`.  The stop came from the CLI wrapper silently
turning the default `jobs=12` into `max_stage_units=12` whenever fail-fast was
enabled.  Thus a concurrency option also limited total work, and a successful
batch returned to the prompt without reaching either a compiler frontier or
the end of the plan.

The two controls are now independent.  `jobs` bounds simultaneous worker
processes.  An omitted `stage-units` passes no admission limit, so a clean run
continues through the remaining dependency plan.  Failure handling is separate:
fail-fast remains the default, while `--continue-after-failure` explicitly
requests complete failure collection.  `--stage-units N` remains the explicit
way to request a bounded resumable batch.  The existing checkpoint's toolchain fingerprint
remains current and can be resumed by the same command.  The native-provenance
bootstrap test file passed 11 tests with 2 skips at this round.

## Round 8 (2026-10-17): every native predicate section has a class ABI

The next full-plan run reached 20/327 admitted units and exposed the census-
selected family directly.  Unit 030 (`IdentityPage._reaches_origin`) tested the
aggregate projection `row[1]`; unit 040 (`RowField.admits`) tested its authored
`item: Any` input.  Neither subject had a `VALUE_TYPE_ABI` row, so SSA correctly
refused to guess a class from an `unknown`/`opaque_ref` payload.

The earlier type-expectation join covered only a dynamic API target such as
`page.fact_type`, and required the subject to be a direct parameter.  Static
`isinstance` targets, loop bindings, field reads and aggregate projections were
therefore outside the mechanism.  This was also the largest independent exact
family in the continue-after-failure census: 19 roots and 102 units in their
reverse dependency closures.  The historical roots are predominantly loop
inputs from concordance-page rows, plus `Any` parameters in `RowField.admits`,
`row_value_id`, `_shape_key` and `parse_identity_log_level`.

ABI settlement now treats every exact native type-predicate subject as a
sectional API input.  If `SOURCE_VALUE_CLASS` or ProgramABI has already settled
an exact class, that fact remains authoritative and the predicate may fold.
Otherwise the subject receives the existing fixed-width native reference
payload (`opaque_ref`, emitted as an integer ctypes word) and a separate
`int64` semantic class tag.  Its closed vocabulary is assembled only from
accepted concordance cells: `CLASS_DECLARATION`, class-valued
`STATIC_SYMBOL_DEFINITION`, `SOURCE_PAGE_FACT_CLASS`, and
`SOURCE_VALUE_CLASS`.  One source cell is retained per class identity; value
occurrences are not copied into a redundant census.  Predicate target cells
are also retained.  There is no live-object inspection, Python class object,
PyObject ABI, inferred dtype class, or synthetic `other` alternative.

`Any` and authored `object` are open API domains.  In particular, `object` is
an accepted supertype, not evidence that the runtime value's exact class is
