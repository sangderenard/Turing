## How claims work

A claim names the functions an item will edit. Two lanes never hold claims
on the same function at once. `fortran_c_shell.py` and
`glsl_deployment_strategy.py` are large, so claim the nested function, not
the file. When an item lands on `main`, the planner deletes its row and adds
a line to "Done" with the merge.

Every item ends with these checks:
- a corpus program (`tests/native_semantics_corpus/`);
- the full typed corpus check, with 0 non-PASS;
- a fuzz seed in the lane's tier, with 0 WRONG and 0 TYPE;
- the gate, with no new names in any of the four parts.

The gate:
- **Authority.** The cloud Linux gate is authoritative (Albert,
  2026-10-24). Do not ask Albert to gate locally. Raise a Windows concern
  only when a change touches vendoring or a Windows build path.
- **How to run it.** `tools/gate/run_gate.sh TREE LOGS`. A pass means no
  new names against `tools/gate/baseline_*.txt`.
- **Install llvmlite first.** Without it, tests fail on main and on the
  branch alike, so the names compare equal and a real regression hides.
  #829 got past the gate that way.
- **Setup.** `pip install -r requirements.txt ziglang pytest pytest-timeout
  llvmlite`.
- **Every backend.** When a change touches lowering that the backends
  share, run the corpus with `TYPED_CHECK_BACKENDS=c,llvm,fortran`, not C
  alone. #859 regressed LLVM silently, and #876 fixed it.
- **Check the part logs.** In a container without the requirements, every
  part fails collection, and `run_gate.sh` still prints an empty "no new
  names" for both trees. Check that each part log ends in a pytest summary.
  F3 makes the script fail in that case.
- **The hazards log** (#888): do not prepend to `TEST_BASELINE_AND_HAZARDS.md`.
  Run `python tools/hazards_log.py new` on your branch, and write the entry in
  the `docs/hazards/<UTC>_<branch>.md` file it creates. Keep one file per PR,
  and edit it if you re-measure. `python tools/hazards_log.py` reads the log.
- **The sympy cache.** #845 removed the test's dependence on it, so a gate
  run no longer needs an empty cache.

Anyone may run the bootstrap and the managed tire at any time without
asking. They take about 20 and 5 minutes in the cloud container:
- bootstrap: `PYTHONPATH=. python3 tools/bootstrap_compiler_whole_program.py
  --output X --continue-after-failure`. Unit results are in

- tire: `tools/build_balloon_tire_native.py --managed-dt --backend c

Whole-class trials are standing frontier sources (doc 39). They work for
