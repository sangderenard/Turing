### R0: an impure-looking middle operand in a chained comparison

- **Records that disagree.** Python's chain semantics evaluate each middle
  operand once. The normalizer can spell only a duplicated occurrence, and
  `_pure_operand` (`ast_control_normalization.py:521`) classes every
  `ast.Call` as effectful.
- **Value.** `int(digits)` and `float(value)`: builtin conversions of a name.
- **Pass.** `_normalize_chained_comparisons`. The refusal is truthful, not a
  lost record. `_pure_operand` is narrower than the language: evaluating a
  builtin numeric conversion of a pure operand a second time, after the first
  evaluation returned, gives the same value and has no effect (**inferred**;
  this holds for `int`/`float` over `str`/`int`/`float`, and does not hold for
  a user class with a side-effecting `__int__`/`__float__`).
- **The trap in the obvious fix.** Hoisting the middle into a temporary
  before the statement is wrong at 9358. There the call sits behind
  `digits.isdigit() and`, so a hoist would raise `ValueError` on non-digit
  input that Python never converts. Any repair must evaluate the middle in
  place: either duplicate it, where the call is proven pure (builtin
  conversion with a pure argument of a builtin type), or bind it once where
  it is first evaluated, so the binding sits inside the BoolOp's arm.
- **Blast radius.** Both whole-program targets, at their first stage: 100%
  of the bootstrap and of the tire.
- **Silent-capable.** Not as it stands, since it is loud. A wrong repair
  (hoisting, or calling every `Call` pure) is silent-capable.
- **Corpus to add with the repair.** `0 <= int(s) <= 9` behind an `isdigit`
  guard; `a < float(x) < b` in a loop; and a refusal case with a user call
  as the middle.

   `lower_control_expression`, `x is None` / `x is not None` where `x`'s
   value-type ABI is a union that admits `NoneType` is lowered through the
   existing exact type-identity predicate (`_native_value_type_predicate`),
   which reads the union's tag (pending for a PlanCall result and replaced

### U1: an IfExp arm narrowed by its `None` test

Repro (focused test `test_a_none_guarded_operator_arm_keeps_its_ifexp_union`):
`s = None if flag > 0 else b; m = {"a": a, "c": None if s is None else s +

skipped it. Fix (`_none_guarded_operator_arm_contract`): in `None if x is
None else E` (and the `is not None` mirror) an operator arm E over `x`
gets the operator's class for `x`'s one non-None class. The silent 0 is
now a loud refusal: a local dict with a union column is refused at
emission (`program_abi_field_slot: no source cell for 'm'`), as
`{"c": None if flag > 0 else b}` already was on `main`.

The new fuzz helper `bump_pick` (`s = maybe_pick(x, y); return None if s
is None else s + 1`) then found a silent wrong answer that `main` has
too: `7 + (-4 if o is None else o)` with `o = bump_pick(n, 2)` gave

WRONG, 1 TYPE, the same on `main`). The conditional joins ran once,
before call-edge settlement gave the call result `s` its class, so the
IfExp never got one (the W1 pattern). Fix: the joins are part of the
settlement fixed point and repeat in every round. Corpus c364–c368, fuzz
snippets over `maybe_pick` and `bump_pick`.
