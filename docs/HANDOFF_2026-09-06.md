## The open defect (native parity)

Everything the retry loop writes through the material record is
invisible at the root buffers, with one recognisable signature:
telemetry exactly 0, inputs rows 2-7 uninitialised, controller untouched,
`last_maximum_*` NaN, `dt_next` 0. Traced through the C of build 10: the
material buffers pass by pointer window -> run_superstep -> step ->
advance (`b3 -> v5 -> v480 -> v222 -> v2`), advance's regions store
through them (`impl_index_assign_double(v2, ...)`), so the writes DO
happen. What undoes them is the rollback path:

1. `saved = state.copy_shallow()` is never lowered. `saved` became a
   FABRICATED float64 scalar input: step formal 46, passed as
   run_superstep's invented input 589, up to the window. The full-native
   gate said `unresolved_calls=0` because the call vanished before the
   gate. `state.restore(saved)` IS lowered (step's `planned_region_2`,
   guarded by `rejected`, four `index_assign_double` into
   inputs/state/output/telemetry from values loaded off that scalar).
2. `targets.mass_max`, `targets.error_limits`, `ctrl.dt_min` projections
   in step are `unresolved_record_projection_receivers` (function
   metadata), so the rejection test compares against receivers the linker
   could not bind.

Traced run (build/managed_dt_trace2_20260906, `--trace` without the
function filter): the trace reached step -> advance -> vector_step and
then timed out at 300 s with a 2 GB file, because the module-lane helpers
(`binary_value` 92,276 activations, `index_select_double`) log every
element of their inner loops. The trace filter (authored functions only,
commit below) was added in response; a filtered traced build into
`build/managed_dt_trace3_20260906` was launched and NOT waited for. To
get the decisive lines: run its executable through
`tools/managed_dt_parity.py build/managed_dt_trace3_20260906 --frames 1
--timeout 300` with `TURING_TRACE_FILE` set, then
`tools/read_native_trace.py <file> --function step_with_dt --first 2000`
and `--grep 'CondBr %t428'` (the `rejected` branch), `--grep 'planned_region_2'`
(the restore), `--grep '%t46'` (the fabricated snapshot input). The two
questions those lines answer: does native reject the first attempt, and
what does restore copy.

## Tools added this session

- `TURING_TRACE_FILE=<path>` + a binary built with `--trace`
  (`tools/build_balloon_tire_native.py --managed-dt --trace ...`) writes
  one line per executed SSA instruction of every authored function
  (module-lane helpers are excluded to keep the file small): function,
  block, instruction text, value. `tools/read_native_trace.py <file>
  --entries` counts activations; `--function step_with_dt --first 400`
  prints one activation; `--grep 'CondBr %t428'` finds a branch outcome.
  Re-emitting from `<build dir>/repository-ssa.pkl` with
  `emit_ssa_to_c(module, root, entry_name=..., trace=True)` takes about a
  minute and is the fast way to check emitter changes.
- `TURING_DEBUG_LINKED_CALLS=1` prints each linked callsite's
  classification (callee outputs, result bindings, returns flags).
- `TURING_DEBUG_PHYSICAL=1` prints C type-union conflicts from the
  emitter's type solver.
- A baseline worktree at a SHORT path (`git worktree add --detach
  C:\Users\alber\AppData\Local\Temp\wtb <sha>` with `NODUS_TENSOR_CORE`
  set) is how the return-merge regression was bisected; a worktree under
  the scratchpad breaks the cffi link on path length.
